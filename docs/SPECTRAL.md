# 分散とスペクトル描画

左側の「光源と分散」で有効化します。
自由描画画面のガラス球の分散例は N-SF11、球、平行投影、128 px、32波長です。
CPU/GPU比較タブにも同じ実験プリセットがあります。通常の起動では、従来の単色モードを維持します。

## 操作

1. 形状・材料プリセットを選び、「複数波長で分散を計算」を選択します。
2. 「材料プリセットの分散データ」は、対応するガラス・結晶のメーカー分散式を使います。屈折率欄の単色値はこのモードでは使いません。450 / 550 / 650 nmの値と出典を表示します。
3. 不均一媒質や任意指定では、対応する分散データ、任意Cauchy近似、または明示的な「屈折率の分散なし」を選びます。データ未登録の材料を自動的に一定値へ置き換えることはありません。
4. 波長数を16、32、64…と増やして像の収束を確認します。8波長は粗いプレビューです。最大256波長。途中の像は一部の波長だけの積算で、色が偏ります。
5. 同じ設定でCPU/GPU比較を実行でき、全画素の差画像と線形RGBの差を保存できます。設定JSON v15にはスペクトル条件と、波長ごとの実際の屈折率・重み・診断を保存します。過去の設定は単色として読み込みます。

初回のGPUシェーダ準備は数秒かかる場合があります。同じ材料・形状・計算法の各波長は同じパイプラインを再利用し、屈折率・位相波数などの値を更新します。波長バッチを順に処理し、各バッチ内の画素と分岐光線をGPUで計算します。総計算量はおおむね波長数に比例します。単精度の判定に合わない画素・波長は従来と同じCPU再計算を使います。

## 材料の扱い

| 材料 | 波長ごとに変更するもの |
|---|---|
| 等方・均一 | n(λ)、局所Fresnel分配、内部直線 |
| 異方・均一 | nₒ(λ), nₑ(λ) または nₓ(λ), nᵧ(λ), n𝓏(λ)、界面の固有偏光・分配・光線方向 |
| 等方・不均一 | n₀をn₀(λ)へ置換。勾配係数と空間分布の式を固定。閉形式・求積・RKF45を各波長で再評価 |
| Common-scale / quadratic / heliconical | 基準のnₒ, nₑを波長依存にし、scale分布・軸方向・回転率を固定。内部モード分配・位相輸送も各波長で評価 |
| 主屈折率を独立に指定できない構成式 | 現段階では「分散なし」でのみスペクトル積算可能。例: 2013 axialの一軸実現、coordinate shear、ENGの磁気的実現、molded変換実現 |

SCHOTTの既存32ガラス、calcite、BBO、LiNbO₃、LBO、KTPに分散式を登録しました。
BBO / KTPの可視・赤外の単色プリセットは、スペクトル時にはそれぞれ同じ分散式を使います。
**スペクトル時のKTPはCASTECHの式、従来の単色値はEKSMAの表**で、丸めや採用式の違いがあります。単色プリセットへ一致するように曲線を補正していません。
LiNbO₃は本アプリでは420–780 nm。他は登録データ範囲と可視380–780 nmの共通部分です。範囲外への外挿は拒否します。

任意Cauchy近似は、λをμmとして

nⱼ(λ) = nⱼ(λref) + Bⱼ [1/λ² − 1/λref²]

です。材料パラメータ欄の屈折率をλrefでの値と解釈します。主軸ごとにBを設定できます。
外部媒質にも同じ形のBを指定できます。初期値0は外部屈折率一定です。
Cauchy係数や不均一媒質への材料曲線の適用は、実測された不均一材料の分散ではなく、明示したモデル仮定です。Hyperbolicでは符号付き構成式の大きさへの仮定に限り、正の誘電率をもつ結晶のデータをそのまま割り当てません。受動性・因果律を保証する分散モデルではありません。

ガラスデータは標準空気に対する屈折率をそのまま使い、空気屈折率の真空補正や温度依存は追加していません。メーカーの吸収データは取り込んでいません。材料名だけで実試料全体の光学特性を再現するという意味ではありません。

## 光源・背景・色の積分

背景は、D65で照明された明暗パターンまたは反射スペクトルを定義したU/D/L/Rの目印を、既知の背景放射輝度として与えます。背景への照明や物体が背景に落とす影は解いていません。
白の相対スペクトル反射率は1、濃いグレーはsRGB値64を線形化した約0.0513です。滑らかな比較パターンは 0.5 + 0.45 sin(3x) sin(3y)。
背景面を向かない光線には同じグレーの環境を与えます。一様白を選んだ場合は全方向白です。
U/D/L/Rの枠にはGaussian関数で明示した青・橙・緑・紫の反射スペクトルを使います。原点は＋、外周は矢印、数字は位置の目印です。目印付き背景はCPUで計算します。任意のRGBパターンからスペクトルを推定する処理はありません。

等幅の各区間の中点λᵢで、同じカメラの位置・方向から単色の全追跡を行い、反射透過・分岐の重みを含むスカラー応答Lᵢを求めます。

(X,Y,Z) = Σᵢ Lᵢ wᵢ,
wᵢ = ∫binᵢ D65(λ) (x̄,ȳ,z̄)(λ) dλ / ∫380⁷⁸⁰ D65(λ)ȳ(λ)dλ.

CIEの1 nmデータを線形補間し、既知の光源×等色関数の積は各1 nm節点で区切ったSimpson則で正確に積分します。この積は区分二次式です。高価な光線追跡だけを区間中点でサンプリングします。したがって一定スペクトルの色は波長数で変わりません。光学応答の波長変化に対しては中点近似なので、波長数の収束確認が別途必要です。

XYZをD65基準の線形sRGBへ変換し、最後にsRGB伝達関数を適用します。自動露光・画像別の正規化はありません。波長範囲を狭めても分母を変えず、その帯域外の光を除去した結果として暗さや色が変わります。表示とPNGは色域外をクリップします。比較・JSON内の線形RGBはクリップ前で、負値や1を超える値も保持します。白点と色域境界付近では小さな丸め差でもクリップ画素として数えます。

位相を含む方式でも、**異なる波長の振幅は合成しません**。同じ波長の内部でのみ従来のモード相関・相対位相の近似を用い、最後に強度をスペクトル積分します。Stokes値は波長ごとに記録し、異なる基底の値を単純平均しません。

## 診断の意味と制約

- 界面数・GPU/CPU処理数・条件外数は「画素×波長」を単位として合計します。
- 打切り寄与・T/Rなどの表中平均は、画素と波長の単純平均です。画像の色を決めるD65・等色関数の重み付き積分とは異なります。最大値は全画素・全波長の最大です。
- GPU準備時間は全波長分の合計です。波長ごとのcache hitも記録します。
- 32波長やCPU/GPU一致は物理精度の保証ではありません。チェック境界の細かな色分離や大きな複屈折位相差は、密な波長サンプルを必要とする場合があります。
- 吸収・回折・別経路間の画像干渉・非線形光学・連続スペクトルの適応サンプリング・任意RGBテクスチャのスペクトル復元は未対応です。既存の幾何光学と内部モード結合の近似範囲を広げるものではありません。

データの出典・ライセンスは [data/spectral/SOURCES.md](../app/data/spectral/SOURCES.md)。
